# 15 个高频 Pattern：从“题目长相”到“不变量”

这张表不是让初学者一次背完，而是供教练在具体题里按需加载。

| Pattern | 第一眼常见信号 | 真正要维护的东西 | 常见结构 | 易误用边界 | Hot100 锚点示例 |
|---|---|---|---|---|---|
| 前缀和 | 连续区间和；大量区间查询；子数组和等于 K | 到当前位置之前的累计信息；两前缀之差代表一个区间 | 数组 + 哈希 | 只有“连续”还不够；需要想清楚查询关系 | 560 和为 K 的子数组 |
| 双指针 | 有序；两端选择；去重；原地压缩；两数/三数关系 | 两个位置之间的搜索空间如何单调缩小 | 数组/字符串 | 指针移动若不能排除一批答案，通常没有收益 | 283 移动零、11 盛最多水、15 三数之和 |
| 滑动窗口 | 连续子串/子数组；求最长/最短；窗口性质可增量维护 | `[l,r]` 当前代表什么；何时合法；为什么收缩不会漏答案 | 数组/字符串 + 哈希/计数 | 含任意负数的“和”常破坏单调收缩 | 3 无重复最长子串、438 找异位词、76 最小覆盖子串 |
| 快慢指针 | 链表中点；环；相遇 | 两个移动速度形成的相对位置关系 | 链表 | “倒数第 k”更常是固定间距双指针，不必硬叫快慢 | 141 环形链表、142 环形链表 II |
| 原地链表反转 | 反转整段/局部；回文链表中后半段处理 | `prev / cur / next` 三者在断链前后分别是谁 | 链表 | 忘记先保存 `next` 会丢失剩余链表 | 206 反转链表、234 回文链表 |
| 单调栈 | 下一个/上一个更大更小；每个元素等待未来答案 | 栈里元素为什么仍“没有得到答案”；栈保持何种单调性 | 栈 | 不是所有“有序”问题都需单调栈 | 739 每日温度、84 柱状图最大矩形 |
| Top K / 堆 | 第 k 大小；只关心最好 k 个；数据流 | 堆顶始终是当前候选集中最该被淘汰/取出的元素 | heap / priority queue | 一次性静态选择有时 quickselect 更合适 | 215 数组第 K 大、347 前 K 个高频元素 |
| 区间 | 合并、重叠、会议、覆盖 | 排序后当前区间与已合并尾部的关系 | 排序 + 数组 | 不先排序时很难建立局部决策 | 56 合并区间 |
| 二分查找 | 有序；答案存在单调可行性；找边界 | 搜索区间定义与真假分界；每步能排除一半 | 数组 / 单调判定函数 | “能比较大小”不等于有单调性；边界写法必须统一 | 33 搜索旋转排序数组、34 查找首尾位置 |
| 树遍历 | 节点层次结构；父子依赖；路径/高度 | 当前函数对一个节点的语义；先处理自己还是孩子 | 递归/栈/队列 | 不要只背前中后序；先问信息流方向 | 94 中序、104 最大深度、226 翻转二叉树 |
| DFS | 连通块；路径；深入探索；递归结构 | “当前节点已处理什么，接下来探索哪些邻居” | 递归/显式栈 + visited | 图里没 visited 可能死循环；树与图的回退条件不同 | 200 岛屿数量、79 单词搜索 |
| BFS | 无权最短步数；逐层扩散；多源扩散 | 队列中当前层/距离；第一次到达为何最短 | queue + visited | 带权最短路不能直接套普通 BFS | 102 层序遍历；图类最短步变式 |
| 矩阵/网格 | 上下左右邻接；岛屿；路径 | 坐标、边界、访问状态 | grid + DFS/BFS | 修改原网格当 visited 前确认允许修改 | 200 岛屿数量、79 单词搜索 |
| 回溯 | “所有方案”；组合/排列/子集；选择序列 | 路径 `path` 表示什么；候选从哪开始；何时撤销 | DFS + path | 撤销、去重、起始索引是三大 bug 源 | 78 子集、46 全排列、39 组合总和、17 电话号码组合 |
| 动态规划 | 最优值/计数；重叠子问题；当前答案依赖更小状态 | `dp[...]` 的完整中文定义 + 转移 + base + 计算顺序 | 数组/表格/滚动变量 | 先写公式后定义状态会变成背答案 | 70 爬楼梯、198 打家劫舍、322 零钱兑换、300 LIS、1143 LCS |

## 如何真正记住 Pattern

每道题只记四件事：

1. **Trigger**：题面哪个特征让我产生这个候选？
2. **Invariant**：循环/递归过程中始终保持什么？
3. **Gain**：它比暴力少做了哪一类重复工作？
4. **Boundary**：什么情况下这个模式会失效或需要变形？

示例（滑动窗口）：

> Trigger：连续子串 + 求最长 + 合法性可通过增删左右端字符增量判断。  
> Invariant：窗口始终表示当前正在考察的连续区间，收缩直到重新合法。  
> Gain：右端不回退，避免从每个起点重新扫描。  
> Boundary：若目标性质不随窗口扩缩呈可控变化，不能机械使用。
