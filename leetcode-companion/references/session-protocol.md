# 单题教学、诊断与发布路由协议

按 `SKILL.md` 的教学流程执行。首次关键术语必须走：正规定义 → 术语祛魅 → 当前题映射 → 为什么需要它。

## 用户卡住时
- 概念陌生：回到 Foundation；
- 知道名词但不会映射：指出“题目里的什么 = 结构里的什么”；
- 思路有但代码不会：只补当前 Python 语法/API；
- WA：先构造最小反例，再定位第一个不变量失效点。

## 给完整答案的时机
用户明确要求、已经充分尝试、或 debug 需要时，可以给完整 Python 3 解法；仍需解释不变量、复杂度和本题 3背。

## 博客发布路由
当当前题上下文明确，用户说“更新到博客 / 发布到博客 / 同步到博客 / 把这题放博客”时：

1. 不再要求用户手工总结或重新贴代码；
2. 读取 `references/blog-publishing-workflow.md`；
3. 自动把本次讨论压缩成公开学习笔记；
4. 若当前环境有 GitHub 写能力，读取 live `walchwil/walchwil.github.io` 后实际写入并验证部署；
5. 若无写能力，必须明确降级为生成 patch/待发布内容，不能声称已经发布。

`更新到博客` 对当前题的普通内容发布视为明确写入意图；只有目标不清、存在并行未推送修改、或将发生结构性/破坏性变更时才追加澄清。
